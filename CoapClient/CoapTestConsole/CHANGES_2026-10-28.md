## 一、已提交：`fdca9ea` — AdsClient → AdsSession 纯替换

### 改动

- `ThinAdsServer` 不再直接持有 `AdsClient`，改为持有 `AdsSession` / `AdsConnection`。
- `Connect` 使用 `AdsSession`，符号表通过 `SymbolLoaderFactory.Create(Connection, SymbolLoaderSettings.Default)` 加载。
- `SimpleCoapClient` 中 4 处直接 ADS 调用收口到 `ThinAdsServer`：
  - 符号读取
  - 通知注册
  - 原始 ACK 读取
  - 通知句柄删除
- `SessionSettings.ResurrectionTime` 保持默认 21 秒：它同时是 FailFast 窗口，清零会让断线后的调用等 5 秒超时。
- 公开 API 未变，命令生命周期组件未改。

## 二、未提交：最小断线重连 + 调用者感知 + IDisposable

### 1. 连接状态与事件

新增 `CoapConnectionState.cs`：

- `CoapConnectionState { Disconnected, Connecting, Connected, Recovering, Disposed }`
- `CoapConnectionSnapshot`：不可变快照，包含 `State`、`Symbols`、`Generation`、`PlcState`、`LastError`，内部还携带对应的 `AdsConnection`。
- `CoapConnectionStateChangedEventArgs`。

`SimpleCoapClient` 新增：

- `ConnectionState`
- `ConnectionSnapshot`
- `LastKnownPlcState`
- `ConnectionStateChanged`

关键不变量：

```
符号表重建完成 → 原子替换快照 → 触发 Connected 事件
```

因此调用者在 `Connected` 回调里使用符号表一定是安全的。符号 API 在非 `Connected` 状态抛 `CoapNotConnectedException`。

### 2. 心跳与重连

- `ThinAdsServer` 内一个后台循环，每 1 秒 `ReadStateAsync`（独立 1 秒取消 token）。
- 断线 → `Recovering`，清空 in-flight 占用，代次 +1。
- 退避 1s → 2s → 5s。
- 恢复时**释放旧 `AdsSession` 并创建新 session**。
  - 实测同一个 `AdsSession` 在本地 `Disconnect()` 后重新 `ConnectAsync()` 不能可靠恢复；新 session 走初始连接路径才稳定。
- 恢复成功后重新加载符号表，再发布 `Connected`。
- PLC 可达但不在 `Run` 时停留在 `Recovering`，不重复重建传输。

### 3. 代次隔离与在途命令

- `CommandContext` 增加 `Generation` / `IsGenerationCurrent()`。
- `CommandInFlightManager` 从“只存 ACK 变量名”改为存 `CommandContext`，支持：
  - 断线 `Clear()`
  - Dispose `Close(ObjectDisposedException)`
- 旧代次的以下路径全部被拦截：
  - `CommandSender` 真正写之前
  - `CommandHandler` 处理通知之前
  - 超时主动读之前/之后
  - `DeleteDeviceNotification` 执行之前
- 避免旧命令用旧 handle 编号误删新连接上的新句柄。

### 4. IDisposable

`SimpleCoapClient` / `ThinAdsServer` 实现 `IDisposable`。

Dispose 顺序：

1. 发布 `Disposed`
2. 取消生命周期 token
3. 有界等待 monitor 退出
4. 停止 `CommandSender` / `CommandHandler` 队列
5. 断开 `Connection` 引用
6. 终结在途命令（`ObjectDisposedException`）
7. 停止 `TimeoutScheduler` 并清空 pending context
8. 释放 `AdsSession`

配套：

- `SingleConsumerQueue` 可停止、可等待、可 drain。
- `TimeoutScheduler` 可停止、可等待、Dispose 时清空堆。
- Dispose 幂等，有界等待（约 2 秒）。

### 5. 行为调整

- `SendAndWaitAck` 非 `Connected` 时返回 faulted task（`CoapNotConnectedException`）；Dispose 后同步抛 `ObjectDisposedException`。
- `GetServerStatusString` 不再做实时 ADS 读取：优先返回快照中的最后已知 PLC 状态，否则返回 COAP 状态名。
- 重复 `Connect`（同目标）直接返回；不同目标抛 `InvalidOperationException`（一实例一目标）。
- 首次 `Connect` 若 PLC 不在 `Run` 或符号表加载失败：不启动心跳，抛异常，不自动重试。
- `CoapNotConnectedException` 的消息从“符号表未加载”改为“连接不在 Connected 状态”。
